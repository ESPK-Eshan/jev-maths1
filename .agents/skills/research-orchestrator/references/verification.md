# Stage verification and issue closure

Read before reviewing or advancing any executed stage. Verification checks actual evidence/artifacts; [journal criticism](journal-stage-critique.md) additionally challenges scientific adequacy and supplies the independent native numeric sidecar. Neither schema validation nor a high score proves scientific truth.

## Assignment and return contract

After producer completion, freeze the outputs and dispatch a fresh `stage_verifier` with original task, applicable stage/phase criteria, immutable inputs/outputs and hashes, commands/receipts, selected skill contracts, allowed inspection/rerun scope and budget. Do not provide the desired verdict or another reviewer's initial conclusions. Use `fork_turns="none"` where genuine fresh context is required and configured supported model/effort; omission inherits history. See [swarm execution](swarm-execution.md) for capacity and evidence access. Missing fresh capacity remains unavailable; producer self-review is not a substitute.

Return a structured receipt containing project/stage/phase/instance/revision and contract IDs, role/settings, inspected inputs/outputs/hashes, checks actually performed, checks missing and why, exact bounded commands/receipts where applicable, verdict, issue severities/evidence locators and concrete next action. Key acceptance to current hashes and contract versions. A material source/artifact change invalidates affected descendants; check the earliest affected obligation rather than blindly rerun the whole study. Reconcile changed loaded skill/reference/script contracts too; unchanged outputs do not make a changed integration contract harmless.

## Required applicable checks

| Check | Evidence that passes | Failure and next action |
|---|---|---|
| Existence/substance | Parseable meaningful content with required fields/rows; intentionally empty outcomes have valid schema/status/reason; images/PDFs actually open/render | Empty CSV, malformed JSON, whitespace/headings-only draft, untouched template or mislabeled image fails; produce actual required output. |
| Execution | Actual exact command/environment/input/config/code IDs, elapsed bounds, exit, produced files/raw logs and meaningful result | Exit zero alone, stale logs, saved scores attributed to a new run, malformed/nonfinite metric or invented execution fails; reconcile or rerun a bounded real check. |
| Scope/controls | Owned edit scope, fixed metric/guards/splits, actual data/license/dependency authority, valid independent units and sealed access | Changed protected evaluator, leaked holdout or unknown ownership blocks corresponding claims/campaign work. |
| Scientific support | Raw/source evidence supports the stated contrast, uncertainty and scope; adverse/contrary findings preserved | Unsupported causal/generalization claim, omitted failures or crucial unread evidence requires repair/narrowing. |
| Artifacts | Numeric tables/plots match authoritative aggregates, transformations/units/uncertainty/captions agree, claims and citations bind evidence, actual render reviewed | Data mismatch, unsupported caption, invented citation or uninspected claimed PDF blocks verified export. |

Actually measured simulators follow [their scoped evidence contract](experiment-campaigns.md); do not reject all simulation or accept placeholder results as a simulator study. A finite offline-policy estimate still needs identification/support. Frozen evaluator-defined candidate failures may be valid unfavorable outcomes; infrastructure nonmeasurement is distinct. Dashboard screenshots, dataset previews and artifact metadata cannot replace full pinned inputs/raw outcomes/render inspection.

Validate the critic's complete score vector, frozen rubric/hash, range/types, exact unrounded equal-weight mean and issue dispositions using the [record helper's actual interface](record-cli.md). Structural checks do not certify truth, freshness or reviewer independence.

## Issue lifecycle

Record issue ID, affected stage/evidence/artifacts, severity and demonstrated impact, original reproduction/source locator, expected behavior, owner, requested fix, closure criterion, fix receipt, independent verification and close reason. Use open → fixing → awaiting verification → verified resolved; explicitly deferred is separate and an unresolved blocker still blocks. Producer assertions cannot close their own issues.

For an execution defect, reproduce the original failure in an isolated bounded fixture when practical, check the fix and a relevant regression. For a source/claim defect, reopen the source and inspect the corrected proposition. For a figure mismatch, check/regenerate against authoritative data. Costly nondeterministic failures may leave residual uncertainty; report it rather than claim resolution from one convenient run. Reuse valid unchanged deterministic evidence and avoid expensive reruns for appearances.

The critic reinspects materially changed evidence with updated hashes and issue dispositions; nonmaterial edits can receive a scoped amendment only after actual impact assessment. Preserve reasoned disagreement; neither majority votes nor persuasive prose close an execution fault. A finding unsupported by inspected evidence is tentative, not an automatic blocker merely because phrased authoritatively.

## Gate and next action

Advance only with all current required verifier/critic/integrity receipts, numerical or separately valid conditional gate and no unresolved mandatory blockers. Fixes use the same stage lineage and [bounded reloop policy](journal-stage-critique.md). Schema repair against unchanged producer hashes is a bounded operational retry; content edits consume the appropriate revision. Repeated identical failures require diagnosis, meaningful strategy change, narrower honest output or a genuine external prerequisite, not nominally complete placeholders.

Gap selection, design, interpretation and final quality also invoke relevant scientific specialists; selected ARS manuscript review retains its exact pre-review, author and re-review prerequisites in [integrations](integrations.md). ARA rigor is optional only for an actual compatible Level-1-passed ARA, not an OKF bundle, and follows its local-read-only/no-code-or-URL-fetch contract. Final stage 20 includes [bounded clean reproduction](reproduction-completion.md); export and backup have their own content-verification boundaries.
