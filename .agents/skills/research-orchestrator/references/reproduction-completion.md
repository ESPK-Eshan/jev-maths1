# Bounded reproduction and honest completion

Read when planning stage 9, approaching stage 20 or deciding the delivered status. Budget the check and scientifically meaningful tolerances in the protocol. [Archive restoration](archive-drive-delivery.md) verifies delivered bytes/history; this reference verifies the declared executable scientific path. Neither alone establishes independent replication.

## Independent clean replay

Give an independent verifier the frozen source/package, documented dependency/OS/runtime recipe, versioned input manifest, expected outputs/tolerances, bounded resources and allowed credential references. Use a clean temporary checkout/extraction and a newly resolved isolated environment. Permit only declared inputs and explicitly declared hash-verified caches. Unrecorded environment variables, private absolute paths, interactive notebook state, hidden files or precomputed target outputs cannot silently supply missing dependencies.

For an empirical route, actually:

1. Regenerate primary reported aggregates and main result table from frozen raw measurements.
2. Rebuild at least one principal measured figure from the shipped script.
3. Run an affordable representative method/evaluator smoke through the documented data-to-metric entrypoint, using the stored candidate/checkpoint where appropriate. Printing cached scores is insufficient.

Use actual allowed inputs for empirical evidence; synthetic fixtures can validate engineering paths only and remain labeled. Full retraining or paid API evaluation is required only when the claim/protocol calls for it and resources authorize it. For review/theory routes, replay applicable extraction/synthesis/computational checks and build rather than invent an empirical experiment. Match scope to [route obligations](pipeline.md).

Persist `.research/reproduction/` receipts with package/checkout/input IDs and hashes, clean-environment resolution, dependency/cache/access references, exact commands, logs/exit statuses, produced and compared outputs, tolerance definitions, duration/resource cost, observed differences and unresolved limitations. Classify demonstrated scope separately as analysis replay, method/evaluator smoke, or full study rerun. This is an operational reproducibility check; independent scientific replication requires its own design/evidence.

Deterministic numeric disagreement blocks the affected result until explained/corrected. Nondeterministic comparisons use justified prespecified tolerances, not newly permissive bounds chosen after failure. Formatting-only byte differences need not be scientific mismatches. An undeclared dependency fails the clean check: repair the supplied recipe/input contract, verify the repair and invalidate only affected results/figures/claims/gates with existing issue/revision history intact.

If restricted data, unavailable paid API or GPU capacity prevents a required component, record precisely what ran, what could not and which completion claim is limited. Analysis replay cannot masquerade as full study reproduction. Preserve source/artifacts and produce the appropriate partial/limited package status rather than claim impossible execution or spend beyond authority.

## Per-deliverable consistency and builds

The inventory binds every requested paper, thesis, supplement and optional editable format to current claim/evidence IDs. Shared results, units, terminology, methods and limitations must agree across artifacts. Each has its own structural/template/bibliography/build/render obligations. A paper PDF cannot satisfy a contracted thesis or donate its format receipt to a thesis; expanded chapters cannot introduce unmeasured results.

A final numerical, bibliography, diagram, caption or citation change reopens affected hash-bound gates before verified export. Unchanged raw experiments do not need blanket reruns; affected claim/source/format/reproduction checks do. Record actual build/log/render hashes and unresolved warnings. Opening an editor or producing source does not prove a compiled inspected PDF. Compiler absence yields source-only/format-pending status, never a manufactured build receipt. See [IEEE](ieee-journal.md), [writing](writing-artifacts.md) and [architecture artifacts](architecture-artifacts.md).

## Completion decision and next action

Keep at least these states distinct in the completion record:

| Dimension | Evidence and permitted claim |
|---|---|
| Study/scientific outcome | Actual applicable route finished, with supported positive/negative/inconclusive/exploratory conclusion and unrun obligations disclosed. |
| Artifact package | Every selected deliverable exists, has current content/format/build/render/reproduction checks for its stated status, or an explicit scoped limitation. |
| Delivery | Local export and, when applicable, standing-authorized remote archive/Drive workflow actually verified under its separate contract. Pending backup remains pending. |
| Human author approval | Required review/declarations/decisions actually supplied. An evidence-audited or author-review-pending draft is not an author-approved submission. |

Plan-only, pilot-only, manuscript or review tasks end at their own declared boundary and cannot claim full-project success, verified novelty, experimental confirmation or a completed remote backup. A valid negative/inconclusive route can complete an honest scoped study and draft without manufacturing a positive finding. Final output names achieved status, evidence scope, actual artifacts and limitations, and precise remaining prerequisite/next action.

Stage 20 passes only applicable current gates including stage 23 citations and this bounded reproduction. Stage 21 preserves findings/failures/provenance and inventory. Stage 22 export keeps local package/remote delivery/human approval distinct and follows [closing-supplement acceptance](archive-drive-delivery.md); acceptance-ready is not accepted. No submission/publication is implicit. Optional ARA research-manager is post-task only; it does not become a live stage-21 prerequisite or alter canonical scientific facts.
